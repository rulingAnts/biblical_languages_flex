# Root-Level GitHub Pages PWA Assets

If you publish this project at `https://rulingants.github.io/biblical_languages_flex/` using the `docs/` folder as the Pages source, most PWA assets can live inside `docs/`. Modern browsers will correctly load the manifest and service worker from there.

However, for best cross-platform install experience (especially older iOS versions and some launch surfaces), you can optionally place the following in the root of the GitHub Pages site (the repository root if you configure Pages to serve from `/`):

## Recommended root files

1. `apple-touch-icon.png` – A raster fallback for iOS install prompt. 180x180 PNG recommended.
2. `favicon.ico` – Windows legacy favicon (can be generated from the SVG).
3. `site.webmanifest` – A simple pass-through pointing to the real manifest inside `biblical_languages_flex/docs/manifest.webmanifest` if you ever change Pages structure.
4. `robots.txt` – Already present inside `docs/`; root copy only if you change source.

You currently have SVG icons and a manifest under `docs/`. These are sufficient for most platforms (Chrome, Edge, Firefox, Android, modern iOS).

## Steps

1. (Already generated) `apple-touch-icon.png` lives in `docs/icons/` and is linked from `index.html`.
2. (Optional) Generate a multi-size `favicon.ico` (16,32,48) from `docs/icons/favicon.svg` if you need legacy Windows/IE support.
3. (Optional) Create a `site.webmanifest` with a redirect or duplicate content if you move hosting root.

Example minimal `site.webmanifest` (only needed if root differs):
```json
{
  "name": "FLEx Interlinear (Web)",
  "short_name": "FLEx Interlinear",
  "start_url": "/biblical_languages_flex/docs/",
  "scope": "/biblical_languages_flex/docs/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#0b5ed7",
  "icons": [
    { "src": "/biblical_languages_flex/docs/icons/favicon.svg", "sizes": "any", "type": "image/svg+xml" },
    { "src": "/biblical_languages_flex/docs/icons/maskable.svg", "sizes": "any", "type": "image/svg+xml", "purpose": "maskable" }
  ]
}
```

## Why not duplicate everything?
Keeping one copy inside `docs/` reduces maintenance. Browsers follow the relative paths from the page origin, so additional root copies are not required unless you change your Pages root or need legacy assets.

## Service Worker Scope
The registration in `index.html` sets scope to `./` which, when served from `https://rulingants.github.io/biblical_languages_flex/`, covers only the `docs/` folder content. If you move the SW to root later, change the registration to:
```js
navigator.serviceWorker.register('/service-worker.js', { scope: '/' });
```
And copy `service-worker.js` + `manifest.webmanifest` + `icons/` to root.

## Ephemeral icon build tooling

Icons were generated by a temporary `icon-build/` folder using Node + `sharp`. After verifying the PNG outputs in `docs/icons/`, you can delete:

```
icon-build/
node_modules/
```

No runtime Node dependency remains; the site is fully static.
